# Механизм агента планирования

`/ai_plan` начинается как управляемый диалог, а затем переходит в агентный
цикл. Сначала бот собирает состояние пользователя, стратегию, цели дня и
неучтённые обязательства. Это подготовка контекста: агент получает не только
список задач, но и понимание ресурсов, ограничений и ожидаемого результата.

Агентное поведение выполняется в `PlanningAgentService.run`. Его цель —
составить реалистичный план дня. Он получает задачи, доступное время, профиль
состояния, историю прошлых дней и записи из `data/agent_memory.md`.

## Конкретная трасса выполнения

Ниже не исключение Python, а трасса исполнения: по ней можно увидеть, какие
функции вызываются при обычном запуске и в каких местах агент принимает
следующее решение.

```text
Пользователь: /ai_plan
│
├─ app/main.py
│  ConversationHandler направляет команду в обработчик
│
├─ app/bot/handlers.py: ai_plan()
│  └─ receive_ai_plan_date()
│     └─ короткий или длинный опрос состояния
│        └─ выбор режима и стратегии, причина выбора
│           └─ вопросы «Главная цель дня?» и «Есть ли неучтённые обязательства?»
│              └─ _run_ai_plan(plan_date)
│
├─ app/bot/handlers.py: _run_ai_plan()
│  ├─ загружает задачи, состояние, историю и agent_memory.md
│  └─ PlanningAgentService.run(...)
│
├─ app/services/planning_agent.py: PlanningAgentService.run()
│  ├─ detect_missing_constraints
│  │  └─ есть «врач»/«приём»/«созвон» без времени?
│  │     └─ вернуть вопрос пользователю → receive_ai_plan_agent_question()
│  │        └─ при подтверждении receive_fixed_time_save() сохраняет время в задаче
│  ├─ goal_is_covered
│  │  └─ цель не покрыта задачами?
│  │     └─ _suggest_goal_tasks() → receive_ai_plan_goal_suggestions()
│  │        └─ выбранные пункты создаются как TaskDraft и добавляются в черновик
│  ├─ analyze_feasibility / find_context_switches / compare_with_history
│  ├─ recommend_reduction / suggest_strategy, если это требуется
│  ├─ create_order
│  │  └─ AIPlanningService.propose(..., planning_context=...)
│  ├─ reflect_plan
│  │  └─ AIPlanningService.reflect(...)
│  └─ вернуть черновик и объяснение в _run_ai_plan()
│
└─ app/bot/handlers.py
   └─ receive_ai_plan_action(): пользователь выбирает исходный или улучшенный
      вариант, либо открывает обратную связь
```

Таким образом, агентность находится именно внутри `PlanningAgentService.run`:
вместо одного запроса «составь план» он каждый раз оценивает текущий контекст,
выбирает нужную проверку или вопрос, принимает результат и лишь затем идёт к
следующему шагу. Telegram-обработчики отвечают за диалог и подтверждения,
сервисы — за анализ и формирование черновика.

## Агентный цикл

Агент работает циклом:

```text
наблюдение → выбор следующего действия → результат инструмента
→ обновление контекста → следующий выбор
```

Ему доступны безопасные действия:

- проверить выполнимость и перегрузку;
- найти переключения контекста;
- предложить сокращение перегруженного плана;
- сравнить день с историей;
- предложить альтернативную стратегию;
- задать пользователю один уточняющий вопрос;
- создать порядок задач;
- проверить порядок через Reflexion;
- показать результат пользователю.

Например, если задача содержит признаки фиксированного события — «приём»,
«врач», «доктор», «созвон» или «встреча» — но у неё нет времени начала,
агент останавливает цикл и спрашивает время и длительность. После ответа
планирование продолжается с обновлённым контекстом. Пользователь может
подтвердить сохранение времени и длительности в самой задаче.

Если цель дня не покрыта задачами, агент предлагает до трёх конкретных
следующих шагов с длительностью. Пользователь выбирает номера; только выбранные
задачи добавляются в план, после чего агент пересобирает порядок.

## Проверка, память и устойчивость

После создания порядка агент запускает Reflexion-проверку. Она оценивает
конфликты с состоянием, стратегией, временем и ограничениями, после чего
пользователь выбирает исходный или улучшенный вариант.

Обратная связь через `/plan_feedback` или кнопку под черновиком сохраняется в
БД и в `data/agent_memory.md`. При следующем запуске агент читает память как
дополнительный контекст. Команда `/agent_memory` показывает текущую память.

Если шаг `create_order` исчерпал три попытки, сохраняется checkpoint с этапом
и контекстом. Кнопка повтора возобновляет работу с этого шага, не повторяя
опрос и выбор стратегии.

Трасса ошибки на этапе составления порядка выглядит так:

```text
PlanningAgentService.run()
  → create_order
    → AIPlanningService.propose()
      → ошибка LLM / некорректный ответ / временная техническая ошибка
    → повтор №1
    → повтор №2
    → повтор №3
  → сохранить planning_agent_checkpoints:
      { step: "create_order", context: ... }
  → показать кнопку «Повторить»
Пользователь нажимает кнопку
  → обработчик retry
    → PlanningAgentService.run(resume_from="create_order", checkpoint_context=...)
```

Checkpoint хранит уже собранные ответы опроса, стратегию, цель, ограничения и
результаты предыдущих проверок. Поэтому повтор не возвращает пользователя к
началу: он продолжает ровно с упавшего шага.

## Границы полномочий

Агент может анализировать, спрашивать, предлагать и пересобирать черновик. Он
не может сам завершать, отменять, переносить задачи или применять расписание:
эти изменения требуют явного выбора пользователя.
